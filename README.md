# epik8s-pyioc: containerized Python IOCs driven by `values.yaml`

`epik8s-pyioc` is for Python IOCs what an ibek support YAML is for C IOCs. It
defines:

1. **`pyioc.yaml`**, a support definition shipped inside the IOC image. It
   declares the IOC's parameters, with types, defaults, ranges and docs.
2. **`pyioc-run`**, the single start command of every Python IOC. It reads the
   IOC entry that ioc-chart writes to `/tmp/iocconfig.yaml`, validates it
   against the spec, and calls the IOC with typed parameters.
3. **`pyioc`**, tooling derived from the spec: checks, JSON Schema, docs, the
   `iocDefaults` block, beamline `values.yaml` validation and a scaffold.

With this, an IOC is deployed from the beamline `values.yaml` alone. You need
no `config/iocs/<ioc>` directory, no `start.sh`, no `template` and no ibek.

```yaml
iocDefaults:                     # generated by: pyioc defaults
  thorlabscct:
    charturl: https://github.com/infn-epics/ioc-chart.git
    devtype: thorlabscct
    devgroup: diag
    image: registry.baltig.infn.it/infn-epics/thorlabscct:0.2.0
    start: pyioc-run
    pva: false
epicsConfiguration:
  iocs:
    cct01:
      devtype: thorlabscct
      iocprefix: SPARC:DIAG:CCT01
      server: 192.168.0.160
      exposure: 10
```

## How it fits epik8s

```
values.yaml ──epik8s-chart──▶ ArgoCD app ──ioc-chart──▶ pod
  iocDefaults[devtype] merged                 /tmp/iocconfig.yaml (the merged entry)
                                              start: pyioc-run
                                                 ├─ finds the spec (by devtype)
                                                 ├─ validates + applies defaults
                                                 └─ entrypoint(instance)
```

Requirements on the charts:

- Select defaults with `devtype` and **never set `template`**. With `template`,
  ioc-chart takes the ibek/jnjrender path. `pyioc validate` reports it.
- ioc-chart must tolerate an empty config directory when an NFS `config` mount
  exists: copy `"$iocConfig/."` instead of `"$iocConfig/*"`. This is the branch
  `fix/empty-config-dir` of ioc-chart. Without it, set `gitinit` with a
  non-empty `config/iocs/<dir>`.

## The specification (`pyioc: 1`)

```yaml
pyioc: 1                         # spec format version (required)
name: thorlabscct                # devtype in values.yaml (required)
description: Thorlabs CCT spectrometers
devgroup: diag                   # default devgroup in the generated iocDefaults
image: registry.example/thorlabscct   # image repository; tag = version
version: 0.2.0
docs: https://...                # becomes `asset` in iocDefaults
entrypoint: thorlabscct10_ioc.ioc:run_pyioc   # module:function(instance) -> int | None
protocols: [ca]                  # ca and/or pva; pva absent -> `pva: false`

parameters:                      # IOC-wide parameters (top level of the IOC entry)
  log_level: {type: enum, choices: [DEBUG, INFO, WARNING, ERROR], default: INFO}

devices:                         # optional: per-device parameters
  multiple: true                 # allow a `devices:` list (several devices, one process)
  prefix: "{iocprefix}:{name}:"  # PV prefix of each list entry
  single_prefix: "{iocprefix}:"  # PV prefix without a list
  parameters:
    server: {type: host, aliases: [ip], required: true}
    exposure: {type: float, default: 8.3, min: 0.01, max: 30000, unit: ms}
```

### Parameter definition

| Field | Meaning |
|---|---|
| `type` | `string`, `int`, `float`, `bool`, `enum`, `host`, `list`, `map`, `any`. A bare string is shorthand, e.g. `port: int` |
| `default` | Value when absent. Without a default, the value is `None` |
| `required` | Missing value is an error |
| `choices` | Values of an `enum`, matched case-insensitively and returned in the declared spelling |
| `min`, `max` | Numeric range |
| `pattern` | Regex for `string` and `host` |
| `unit`, `description`, `example` | Documentation; also used in the JSON Schema |
| `aliases` | Other keys accepted for the same parameter, e.g. `ip` for `server` |

Values are coerced from YAML scalars. Values set through `iocparam`, which
ioc-chart flattens to top-level `name: value`, arrive as strings and are
accepted. Booleans accept `true/false/yes/no/on/off/1/0`.

### Instance resolution rules

- `iocprefix` is required. `iocname` comes from the chart.
- Without `devices:`, there is one device with prefix `single_prefix`, and its
  parameters are read from the top level.
- With `devices:`, each entry needs `name` (or an explicit `prefix`) and may set
  `disable: true`. Device parameters set at top level are **defaults for every
  entry**.
- Keys that are not parameters are ignored at top level, because chart settings
  live there. Inside `devices` entries they produce a warning, which catches
  typos.
- Every error is reported at once. `pyioc-run` exits with status 2 before
  starting anything.
- Parameter names may not use keys interpreted by epik8s-chart or ioc-chart
  (`template`, `host`, `serial`, `start`, `image`, `devices`, ...; see
  `RESERVED_KEYS`). `server` plus `port` is allowed: ioc-chart then checks that
  the device is reachable before the IOC starts.

### Runtime contract for the image

- Install the IOC package and `epik8s-pyioc`.
- Register the spec as a package entry point:

  ```toml
  [project.entry-points."epik8s.pyioc"]
  thorlabscct = "thorlabscct10_ioc"       # package that contains pyioc.yaml

  [tool.setuptools.package-data]
  thorlabscct10_ioc = ["pyioc.yaml"]
  ```

  One image may contain several IOCs. `pyioc-run` picks the one matching the
  entry's `devtype`. Without entry points, it uses `$PYIOC_SPEC` or
  `/epics/pyioc/pyioc.yaml`.
- The IOC must run as an arbitrary uid (ioc-chart uses 1000). `pyioc-run` sets
  `HOME=/tmp` when the home directory is not writable.
- The entrypoint receives an `Instance`:

  ```python
  def run(instance):            # epik8s_pyioc.Instance
      instance.iocname, instance.iocprefix
      instance.log_level        # IOC parameter (also instance["log_level"])
      for device in instance.devices:
          device.name, device.prefix, device.server, device.exposure
      instance.raw              # the whole merged entry, for anything else
  ```

## Tools

```sh
pyioc init mydev --image ghcr.io/infn-epics/mydev   # new IOC project (spec, package, Dockerfile)
pyioc check   -s src/pkg/pyioc.yaml                 # validate the spec
pyioc docs    -s ...                                # Markdown parameter tables
pyioc schema  -s ... [--fragment]                   # JSON Schema (or an if-devtype clause for the beamline schema)
pyioc defaults -s ... [--tag 0.2.1]                 # iocDefaults block
pyioc render  -s ... instance.yaml                  # resolved instance, as pyioc-run sees it
pyioc validate -s ... deploy/values.yaml            # every IOC of this devtype in a beamline (for CI)
pyioc list                                          # IOCs installed in this environment
pyioc-run [config] [--check]                        # start (default config: $IOC_CONFIG or /tmp/iocconfig.yaml)
```

Without `-s`, the tools use `./pyioc.yaml`, or the IOC installed for `--devtype`.
Inside an image, `pyioc docs --devtype thorlabscct` documents the IOC that the
image ships.
